# HTC 是怎样从“时间感”走向“人类式记忆核心”的

> 记录范围：2026-07-16 至 2026-08-11
>
> 文档类型：Explanation
>
> 状态：阶段性产品历程

Human Temporal Continuity（HTC）并不是从“做一个记忆数据库”开始的。它最初来自一个很朴素的期待：长期聊天的 AI 应该像认识一个人的人一样，知道现在是什么时候，也知道用户说的是哪个时候。

当用户深夜说“太晚了，明天再做吧”，第二天的 AI 不应该还把“明天”当成一个静态词语；当用户在多个会话里谈工作、关系、生活和过去，AI 不应该因为线程变化就把人切成几份；当一段负面经历与当前问题有关，AI 也不应该为了证明自己记得，就主动把它重新翻出来。

HTC 的产品方向正是在这些真实问题中逐步形成的。它经历了协议、产品工作台、可视化时间线和沉浸式旅程等多次探索，最后才把核心收敛到三个问题：记什么、何时使用，以及由谁控制。

## 1. 起点不是存储，而是时间

时间问题是项目最直接的入口，但 2026-07-16 的首版定义已经不只讨论日期解析，也包含选择性记忆、遗忘、计划与事实的区别、纠正、召回与表达分离，以及用户治理。时间让这些问题第一次以一个无法回避的方式连在了一起。

普通聊天记忆容易把“昨天”“明天”“最近”“那几年”当作普通文本保存，但这些词只有绑定当时的对话时间、时区和语境才有意义。时间继续向前后，记忆也需要重新表达：昨天的“明天再做”，到了今天应当变成“原计划今天继续”；日期过去以后，如果没有新的完成证据，结果仍然只能是未知。

这个问题很快暴露出：时间并不是记忆对象上的一个 `timestamp` 字段。HTC 至少需要区分：

- 事情发生的时间；
- 系统得知事情的时间；
- 相对表达所依赖的锚点；
- 计划或预计发生的时间；
- 一个状态真正有效的时间范围；
- 当前可信的日历时间；
- 用户仍处于哪一段连续生活经历。

因此，HTC 从一开始就不是“把聊天存下来再搜索”，而是试图维护一个人在时间中的连续状态。

## 2. 真实对话把问题从时间推向记忆

随着多日对话积累，这些抽象原则获得了更具体的行为边界。仓库中的参考轨迹是从真实交流问题中提炼出的去标识、合成 fixture，不保存原始个人历史。

同一个人会在不同线程里谈论同一段关系、同一个朋友、同一份工作或同一个未完成计划。新会话不是新人，旧会话也不是独立档案。由此形成了项目最稳定的一句话：

> **线程很多，但人只有一个。HTC 的产品边界是用户级记忆，不是会话级记忆。**

真实交流还暴露了几类仅靠检索解决不了的问题：

1. 语音转写可能把同一个人的名字写错，后来的明确纠正必须覆盖当前投影，但仍保留来源历史。
2. “可能”“大概率”“还没定”不是低质量文本，而是事实本身的不确定性。
3. 计划日期过去不等于计划已经完成；可选建议也不等于已经安排。
4. 一次强烈的难过或焦虑不能被固化成永久人格标签。
5. 一条记忆即使与当前话题相关，也可能只适合帮助内部理解，不适合主动说出口。
6. 用户说“记住，但不要主动提”，表达的是对记忆用途的授权，而不只是另一条生活事实。

于是 HTC 的对象不再只是事件，还包括状态、意图、用户明确表达的意义、相处偏好、纠正和表达边界。

## 3. 第一次收窄：不再优先做新的记忆协议

项目早期曾考虑把 HTC 做成跨 Agent 的记忆协议或一致性标准。2026 年 7 月的两轮行业扫描显示，存储、向量检索、时态知识图谱、Agent 用户建模和记忆协议已经有大量成熟方案。

这并不意味着 HTC 没有价值，而是意味着价值不能建立在“又一套 memory CRUD”上。真正仍然缺少统一答案的问题是：

- 未来意图与已发生事实如何区分；
- 相对时间如何完整锚定；
- 用户纠正后旧版本如何失效；
- 一次情绪如何避免变成身份判断；
- 相关记忆为什么有时必须保持沉默；
- 不同后端如何表现出一致、克制、可验证的行为。

行业扫描当时直接支持的是一个后端中立的语义合规层，并没有自动得出“先做产品 Core”的结论。真正改变交付顺序的是 2026-07-18 对项目初衷的再次澄清：用户要的首先是一个真的能长期理解人的记忆核心，而不是先发布一套标准。

项目由此从“协议优先”转向“核心优先、体验验证、标准后置”：先实现 Human Memory Core，用“明天再做”和“情绪连续性”两条最小轨迹验证行为，再接入真实 Adapter，最后提炼适配规范和一致性测试。标准化没有被放弃，只是必须建立在真实实现上。

## 4. Workbench 解决的是控制，不是聊天

当产品边界从单个会话提升到用户级记忆后，HTC 需要一个让用户看见和治理记忆的界面，于是出现了 Memory Workbench。

Workbench 从来不应该是另一个聊天产品。它是用户自己的记忆控制台，用于回答：

- HTC 记住了什么；
- 这条记忆来自哪些会话；
- 时间为什么被理解成这样；
- 哪些事实仍然有效，哪些已经过时或被纠正；
- 哪些内容可以跨会话内部使用；
- 哪些内容禁止主动提及；
- 用户如何修改、合并、隐藏、撤回和删除。

最初的静态原型设计了 Timeline、Inbox、Memory Detail、Conversations、Recall Preview 和 Settings 六个入口。这一阶段证明了“用户级记忆线”和“用户控制感”在产品上可以被表达，但它使用的是合成数据，还没有实现真正的记忆核心。

## 5. Memory Timeline 是一次必要但不充分的探索

为了表达“一个人在时间中持续前进”，项目随后把 Timeline 设计成一条纵向、蜿蜒的路。用户滚动时，一个人沿路经过不同人生章节，过去从远处走来，“现在”成为旅程的终点。

这一方向先后经历了二维页面、剪影氛围和 Three.js 三维世界。它帮助项目确认了几件事：

- 时间线应该按真实时间顺序向现在推进，而不是从现在倒着回看；
- 记忆不是平铺的卡片列表，而是有远近、阶段和连续感的生命经历；
- Workbench 可以拥有区别于普通后台管理系统的情绪氛围；
- 视觉隐喻能够解释 HTC，但不能代替 HTC。

最后一点最重要。一个会走的小人、一条漂亮的路和富有氛围的场景，都不能证明系统真的会记忆。只要后台仍然不知道“明天”是哪天、不知道计划是否完成、不知道什么不应说出口，它就仍然只是一个概念展示。

因此，Memory Timeline 被重新放回正确的位置：它是用户浏览记忆的一种界面，而不是 HTC 的产品本体。

## 6. 真正的核心在三个判断

到 2026 年 8 月，HTC 的核心逐渐收敛为三个连续判断。

### 6.1 记什么

HTC 不是尽量多记，而是判断哪些内容会影响未来理解：

- 经历与事实；
- 当前或历史状态；
- 尚未闭环的意图；
- 用户明确表达的意义；
- 人际关系和称呼；
- 用户希望 AI 如何与自己相处；
- 对旧记忆的纠正、撤回和授权。

模型可以提出候选，但不能直接把推测写成长期事实。测试、引用、假设、角色扮演和无法确认的内容默认不能成为现实记忆。

### 6.2 何时使用

检索相关不等于适合表达。HTC 必须把“内部想起”和“主动说出”拆成两次判断。

一次召回至少应区分：

- `allowed_to_use`：当前回答可以自然使用；
- `internal_only`：只用于调整理解、语气或建议；
- `confirm_first`：使用前需要确认；
- `suppressed`：本次明确禁止使用或表达。

负面情绪默认应降低主动提及权。它们可以帮助系统理解用户此刻可能承受的压力，却不应被反复复述，更不应被永久固化成“你一直是一个焦虑的人”。克制不是记忆能力不足，而是 HTC 的核心能力；新的、明确且当前相关的安全风险证据仍应进入独立的安全流程，不能被普通的表达抑制规则遮蔽。

### 6.3 由谁控制

HTC 可以静默工作，但不能静默决定。

用户拥有最终控制权：查看来源、纠正时间和实体、合并重复记忆、改变重要性、禁止主动提起、撤回、删除和导出。用户对自己经历与意义的明确解释，优先于模型推断、旧摘要和语音识别结果。

这三项最终构成完整闭环：

```text
记忆形成 -> 记忆使用 -> 记忆治理
```

## 7. “人类式记忆”还意味着什么

讨论继续后，HTC 的记忆范围也从“过去发生了什么”扩展到更接近长期相处所需要的能力。

### 7.1 前瞻性记忆

记住未来要做的事，同时诚实保留 `planned / active / waiting / paused / completed / cancelled` 和“结果未知”。

### 7.2 来源记忆

知道一件事由谁说出、在哪个会话中被观察、是否来自用户直接陈述、模型推断、引用还是工具证据。

### 7.3 重构与演化

后来发生的事情会改变对过去的理解。HTC 应追加修正、替代和状态变化，而不是粗暴覆盖，也不能让已经失效的旧版本重新进入回答。

### 7.4 遗忘与衰减

遗忘不是故障。普通细节、短期情绪和已失效状态应逐渐降低召回与表达权；用户要求物理删除时，则必须真正删除相应数据及派生结果。

### 7.5 场景隔离

工作会话、私人倾诉和健康话题不能共享同一表达权限。记忆可以跨会话归属于同一个用户，但每次使用仍必须受当前目的和场景约束。

### 7.6 相处记忆

HTC 需要记住的不只是“用户是谁”，还有“用户希望 AI 如何与自己相处”：不要反复询问已经回答的问题、不要主动提某类内容、不要把不确定说成确定、不要用内部字段替代自然交流。

### 7.7 状态快照

状态快照是近期提出、仍待验证的能力。当前状态可以作为短期、可修正的观察，帮助 AI 调整回应，但不应压缩成一个权威总分，也不能被当作医学诊断或永久人格。如果后续实现，它应默认短期有效、用户可见可改，并与长期记忆分开。

## 8. 当前确认的产品结构

截至 2026-08-11，HTC 的目标结构已经较为清楚：

```text
聊天产品或 Agent
        |
        | Adapter 提交带来源的 observation
        v
HTC Core（本地静默运行）
        |-- 时间定位
        |-- 候选记忆提取
        |-- 准入、整合与纠正
        |-- 遗忘与状态演化
        |-- 情境召回与表达门控
        `-- SQLite 本地存储
        |
        | 返回用途绑定、短期有效的 Recall Package
        v
聊天产品继续自然回应

Memory Workbench（本地 Web）
        `-- 用户查看、纠正和控制自己的记忆

公开网站
        `-- 只负责介绍产品，不承载用户私有记忆
```

近期讨论提出了一项工程建议：使用 Python 实现 HTC Core，保留 TypeScript + React 作为 Workbench，并让两端通过语言无关的 JSON Schema 协议通信。Python 更方便进行时间、文本、LLM 与本地服务实验；React 则适合继续承担可视化治理职责。但这一方案尚未经过工程设计评审，仓库当前锁定的边界只有“本地 Core + SQLite 或等价存储”，具体语言和进程结构仍待决定。

这仍是设计方向，不代表 Core 已经实现。当前仓库中可运行的主要成果仍是静态 Memory Workbench 与三维 Timeline 原型。

## 9. HTC 现在是什么，也不是什么

HTC 现在可以被更准确地定义为：

> **面向长期 AI 关系的用户级时间记忆核心：它跨越多个会话，识别持续影响一个人的经历与意图，在恰当的语境中安静地参与理解，并把最终控制权留给用户。**

它不是：

- 新的陪伴聊天产品；
- 聊天记录浏览器；
- 自动人生总结器；
- 人格或心理诊断系统；
- 另一套向量数据库；
- 只属于某个 Agent 的 Skill；
- 以展示性时间线代替真实记忆能力的前端项目。

## 10. 下一步不是继续装饰时间线

HTC 下一阶段最重要的里程碑，是实现一个可测试的最小 Core 闭环：

```text
observe -> candidate -> decide -> memory -> recall -> explain
```

第一组测试应该证明：

1. 多个会话归属于同一个用户级记忆空间；
2. “明天再做”能够绑定正确的时间锚点；
3. 计划日期过去以后，结果仍可保持未知；
4. 用户纠正的人名和事实不会被旧版本重新覆盖；
5. 测试句、引用和假设不会成为现实记忆；
6. 负面状态默认只参与内部理解，除非用户主动打开话题；
7. 用户设置“不要主动提”后，新的 Recall Package 会立即压制相应内容；
8. 用户能够从 Workbench 查看每条记忆的来源与使用理由。

当这些行为真正运行起来，HTC 才从一套产品理念变成一个可验证的产品核心。之后，Memory Timeline 才值得继续成为那个核心的可视化入口。

## 11. 仍然没有答案的问题

HTC 已经有了较稳定的方向，但仍有重要问题必须通过实现和使用回答：

- 哪些普通记忆可以自动写入，哪些必须等待用户确认；
- 短期状态应如何衰减，何时值得升级为长期意义；
- 不同聊天宿主如何安全、明确地提交 observation；
- 本地服务如何打包、启动和升级，才能真正保持静默；
- Recall Policy 如何既避免遗漏，又避免过度调用私人历史；
- 用户愿意花多少精力治理自己的记忆；
- “被持续理解”能否被稳定地感知和验证，而不只是概念上的认同。

这些问题不应该靠继续增加字段提前回答。HTC 需要一个真实运行、能够犯错、允许纠正的 Core，从使用中找到边界。

## 结语

HTC 的历程并不是从一个完整产品计划走向实现，而是从一个很个人的期待开始，经过真实对话不断发现：人类式记忆最难的地方从来不是保存。

真正困难的是，知道什么值得留下，知道过去、现在和未来之间发生了怎样的变化，知道此刻应该想起什么，也知道什么时候最好不要说。

> **线程很多，但人只有一个。**

这句话最初描述的是跨会话问题，现在也成为 HTC 的边界：不是让 AI 占有一个人的全部历史，而是让它在时间流逝后，仍能以克制、诚实、可纠正的方式理解同一个人。
